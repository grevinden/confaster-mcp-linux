# Запуск и подключение

## Аргументы

```text
confaster-mcp --export-root <путь> [--extension-root <путь>]...
              [--disabled-tool <имя>]... [--no-index-admin]
```

| Аргумент | Описание |
|---|---|
| `--export-root <путь>` | корень выгрузки основной конфигурации. Без него регистрируются только инструменты справки |
| `--extension-root <путь>` | корень выгрузки расширения в любом поддерживаемом формате; можно указывать несколько раз. Допускается `имя|путь`, чтобы задать имя без разбора `Configuration.xml` |
| `--disabled-tool <имя>` | отключить инструмент по имени; можно несколько раз |
| `--no-index-admin` | запретить инструменты, меняющие индекс (`sync_index`, `switch_export_root`, `reindex_1c_help`) |

Сервер работает по MCP поверх stdin/stdout, поэтому логи пишет только в stderr
с префиксами `MCP_LOG:` и `HELP_STATUS:`.

## Форматы выгрузки

Сервер работает с исходниками в двух форматах: полная выгрузка из Конфигуратора
и проект 1C:EDT. Формат определяется по содержимому каталога, отдельного
переключателя нет.

### Выгрузка из Конфигуратора

```text
/home/user/Выгрузки/УТ/
├── Configuration.xml
├── ConfigDumpInfo.xml
├── CommonModules/УчетНДС/Ext/Module.bsl
├── Catalogs/Номенклатура/Ext/ManagerModule.bsl
└── Documents/ЗаказПокупателя/Ext/ObjectModule.bsl
```

XML-файлы объектов дают метаданные: реквизиты, табличные части, формы, команды.
Работают все инструменты, включая `list_objects`, `get_object_structure`
и `find_function_in_object`.

### Проект 1C:EDT

```text
/home/user/workspace/OpenIntegrations/
├── DT-INF/PROJECT.PMF
└── src/
    ├── Configuration/Configuration.mdo
    └── CommonModules/OPI_Функции/Module.bsl
```

Индексируются все `*.bsl` проекта: общие модули, модули объектов, модули форм,
модули команд. Поиск по коду, символьные инструменты, ссылки, контекст и граф
вызовов работают так же, как на выгрузке Конфигуратора.

Ограничение: метаданные EDT лежат в `*.mdo`, и сервер их не разбирает. Поэтому
`list_objects`, `get_object_structure` и `find_function_in_object` на
EDT-проекте вернут пустой результат. Это поведение оригинального сервера,
а не потеря порта: на одном и том же EDT-проекте оригинал и порт отвечают
одинаково. Если нужны объектные инструменты, подключите ещё и выгрузку
Конфигуратора.

Оба формата можно смешивать: основная конфигурация — дамп Конфигуратора,
расширение — проект EDT (или наоборот). Каждый корень обрабатывается отдельно.

### Индекс

Индекс SQLite создаётся при первом запуске в `<корень>/.index/onec_search.db`;
при изменении файлов `sync_index` обновляет только изменившееся.

### Расширения

Расширения задаются отдельными корнями `--extension-root`, в любом из двух
форматов, можно несколько. В выдаче каждое видно как отдельная конфигурация,
а у инструментов появляется параметр `configuration` (`"основная"` или имя
расширения). Имя берётся из `Configuration.xml`; для EDT-расширения, где такого
файла нет, — из имени каталога. Задать имя явно можно через
`--extension-root "МоеРасширение|/путь"`.

## Подключение MCP-клиента

После установки пакета:

```json
{
  "mcpServers": {
    "1c-search": {
      "command": "/usr/bin/confaster-mcp",
      "args": ["--export-root", "/home/user/Выгрузки/УТ"]
    }
  }
}
```

Из репозитория (без установки):

```json
{
  "mcpServers": {
    "1c-search": {
      "command": "/путь/к/confaster-mcp-linux/scripts/run-mcp.sh",
      "args": ["--export-root", "/home/user/Выгрузки/УТ"]
    }
  }
}
```

С расширением:

```json
{
  "mcpServers": {
    "1c-search": {
      "command": "/usr/bin/confaster-mcp",
      "args": [
        "--export-root", "/home/user/Выгрузки/УТ",
        "--extension-root", "/home/user/Выгрузки/МоеРасширение"
      ]
    }
  }
}
```

Формат секции `mcpServers` одинаков для большинства клиентов (Claude Desktop,
OpenCode и т.п.); в клиентах с другим форматом важны только `command` и `args`.

## Типовой сценарий работы

1. Запустить сервер, дождаться индексации (первый запуск дольше).
2. `sync_index` — обновить индекс после правок.
3. `semantic_find` / `search_code` — найти код по смыслу или тексту.
4. `find_symbol`, `smart_find`, `get_symbol_context` — перейти к реализации.
5. `find_references`, `impact_analysis`, `get_function_context` — оценить связи.
6. `stats` — проверить, что проиндексировалось.

Справка платформы 1С (`search_1c_help` и др.) входит в поставку: каталог
`1c-help/8.3.27.2342` рядом с приложением или `/usr/share/confaster-mcp/1c-help`
в пакете. Установленная платформа 1С не требуется. Порядок поиска:
`CONFASTER_1C_HELP_PATH`, `1c-help/` рядом с бинарником,
`/usr/share/confaster-mcp/1c-help`, затем установленная платформа.

Индекс справки строится один раз и хранится в
`$XDG_CONFIG_HOME/Confaster/HelpIndex/help.db` (при пустой переменной —
`~/.config/Confaster/HelpIndex/help.db`). В нём три раздела: `syntax`
(объектная модель и встроенный язык), `language` (операторы и выражения),
`query` (язык запросов). Раздел задаётся параметром `category` у
`search_1c_help`:

```json
{"query": "ПОМЕСТИТЬ", "category": "query", "limit": 5}
```

Проверить индекс целиком, не трогая рабочий: `scripts/check-help-index.py`.
