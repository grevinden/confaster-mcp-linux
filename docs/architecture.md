# Устройство

## Схема

```text
MCP-клиент ⇄ stdin/stdout ⇄ Program.Main
                              │
                        McpServer (JSON-RPC 2.0)
                              │
                        ToolRegistry ── 21 инструмент
                         │        │
     IndexManager ────────┘        └────── HelpIndexer / HelpDatabase
     FileScanner, MetadataParser            (справка платформы 1С)
     BslAstParser (tree-sitter)
                         │
                   SQLite-индекс
             <корень>/.index/onec_search.db
```

### Program

Разбирает аргументы, регистрирует нативные библиотеки, строит `ConfigRoots`
(основная конфигурация + расширения), создаёт `ToolRegistry` и читает строки
stdin в цикле. Каждая строка — JSON-RPC-сообщение; ответ пишется в stdout.
Диагностика — только в stderr.

### McpServer

Реализует `initialize`, `notifications/initialized`, `tools/list`, `tools/call`,
`ping`. `serverInfo.name` — `1c-search`, версия берётся из метаданных сборки.

### ConfigRoots

Описывает одну или несколько конфигураций (основная + расширения). Для
расширения имя определяется по `Configuration.xml` (реквизит `ObjectBelonging`
и имя), кешируется в индексе. `IndexRoot` — каталог с базой индекса.

Формат корня определяется по содержимому каталога:

- выгрузка Конфигуратора — `Configuration.xml`, каталоги объектов
  (`Catalogs/.../Ext/Module.bsl`), метаданные читаются из объектных `*.xml`;
- проект 1C:EDT — `DT-INF/PROJECT.PMF` и `src/` (`src/CommonModules/.../Module.bsl`),
  метаданные в `*.mdo` не разбираются, индексируются все `*.bsl`.

Оба формата поддерживаются для основной конфигурации и для расширений.

### Индекс

SQLite с FTS5:
`indexed_files`, `symbols` (+ `symbols_fts`), `calls`, `objects`,
`object_items`, `object_synonyms`, `regions`, `meta`, `symbol_weights`,
`domain_aliases`. Инкрементальная синхронизация сравнивает `mtime` и размер
файлов, переиндексирует только изменившиеся. Для поиска используется FTS5
с триграммами, поэтому подстроки ищутся без префиксных костылей.

### BslAstParser

Обёртка над tree-sitter: `ts_parser_parse_string` строит дерево, обход извлекает
процедуры, функции, параметры, вызовы, регионы, директивы компиляции.
Требует `libtree-sitter-bsl.so`; при его отсутствии сервер работает в урезанном
режиме (текстовый поиск и справка доступны).

### Справка 1С

`HelpIndexer` ищет справку в порядке приоритета:

1. `CONFASTER_1C_HELP_PATH` — явный путь к каталогу с `.hbk`;
2. `1c-help/` рядом с приложением (бинарный архив, сборка из исходников);
3. `/usr/share/confaster-mcp/1c-help` (пакет `.deb`);
4. установленная платформа: `/opt/1cv8*/x86_64/<версия>`,
   `/opt/1C/1cv8*/x86_64/<версия>`, Windows-пути.

Каталог с `.hbk` может быть указан напрямую или содержать подкаталоги версий —
берётся старшая. В Linux-раскладке платформы файлы лежат в корне каталога
версии, в Windows — в `bin/`.

`HelpIndexer` собирает три книги в один FTS5-индекс; раздел задаётся
категорией. Для двух книг в поставку входят английские дубли — они дают текст
повреждённых страниц:

| Файл | `category` | Содержание |
|---|---|---|
| `shcntx_ru.hbk` | `syntax` | объектная модель и встроенный язык |
| `shlang_ru.hbk` | `language` | операторы и выражения языка |
| `shquery_ru.hbk` | `query` | язык запросов |
| `shlang_root.hbk` | `language` | английский дубль `shlang_ru.hbk` |
| `shquery_root.hbk` | `query` | английский дубль `shquery_ru.hbk` |

`HbkParser` разбирает контейнер 1С (таблица записей + поток `FileStorage`), а
внутри ищет zip по локальным заголовкам `PK\x03\x04` и полю `compressed size`.
`ZipArchive` не используется: у `shlang_ru.hbk` два EOCD, у `shquery_ru.hbk`
его нет вовсе, поэтому стандартный ридер видит только `shcntx_ru.hbk`.

Страница определяется по содержимому (после BOM и пробелов идёт `<`), а не по
расширению: в `shquery_ru.hbk` страницы называются `KeyWordsSELECT`,
`WhereStatement`, `JOIN` и т. п., без `.html`. Записи без разметки — шаблоны
`*.st`, `__categories__`, рисунки — пропускаются. Индексируется 25 683 темы:
`syntax` 25 520, `language` 37, `query` 126.

Запись принимается, только если совпали и `uncompressed size`, и CRC-32 из
локального заголовка. Тринадцать страниц в русских книгах повреждены: их
deflate-поток обрывается или даёт другой размер. Для двенадцати из них
индексируется одноимённая страница из английского дубля: заголовок получает
суффикс ` (en)`, в начало текста добавляется пояснение. Страница `8` в
`shlang_ru.hbk` повреждена, английского дубля у неё нет — это единственная
потеря из 25 684.

Рядом с книгами лежит `search-aliases.tsv` — русские поисковые синонимы для
восстановленных страниц (`language/struct_TryCatch` → `Попытка`,
`query/DATEADD` → `ДОБАВИТЬКДАТЕ`). `HelpAliases` читает файл при старте,
`search_1c_help` при точном совпадении запроса с синонимом ставит такую тему
в начало выдачи. Это не меняет FTS-индекс и не требует переиндексации:
синонимы действуют поверх обычного поиска.

`topic_id` — `<версия>/<category>/<имя записи без расширения>`. Имена в разных
каталогах справки иногда совпадают (например, `syntax/Parent` у 68 типов
метаданных), тогда `get_1c_help_topic` возвращает первую совпавшую тему.

Ход индексации пишется в stderr строками `HELP_STATUS:parsed:<category>:<n>` и
`HELP_STATUS:fallback:<category>:<n>`; итог — `HELP_STATUS:ready:<версия>:<n>`.
Английский дубль нужен только для повреждённых записей: если его нет рядом с
русской книгой, эти страницы просто не попадут в индекс.

Индекс лежит в `$XDG_CONFIG_HOME/Confaster/HelpIndex/help.db`, при пустой
переменной — в `~/.config/Confaster/HelpIndex/help.db`. Инструменты справки
доступны всегда, платформа 1С на машине не требуется.

## Нативные библиотеки

| Библиотека | Источник |
|---|---|
| `libe_sqlite3.so` | NuGet `SQLitePCLRaw.lib.e_sqlite3`, приезжает в `runtimes/<rid>/native/` |
| `libtree-sitter-bsl.so` | `scripts/build-tree-sitter.sh`: рантайм tree-sitter + грамматика BSL |

Обе ищутся рядом с приложением, поэтому `dist/`, `.deb` и бинарный архив
самодостаточны.
